## Open questions

- OQ-30 (§5.3 set_aside "enum") SAM.gov publishes ~20 set-aside codes (SBA, 8A, HZC, SDVOSBC, WOSB, EDWOSB, ...) and Indian portals use free-text reservations. `set_aside` and `reservation` are stored as short text codes (normalised in app/core/normalize) rather than a Postgres enum, so a new code never breaks ingestion. Matching (M3) should compare codes, not display names.
- OQ-31 (§5.1 / M2-01) Where does the `sources` row sync run? On API startup (lifespan, best-effort: a DB outage logs a warning and the API still boots) and inside `run_source`'s caller (M2-16 job entrypoint should call `sync_sources` first). The FixtureAdapter lives in tests (tests/adapters/fixture_adapter.py) and is registered only for the duration of a test via `registry.temporarily()`, so no `fixture` source row appears in real databases.
- OQ-32 (M2-03 vs M2-01 order) `sources`/`source_runs` are created by migration 0003 already in M2-01 (acceptance needs them); 0003 currently revises 0001_m0_foundation and is re-pointed to 0002_m1_profile by the orchestrator at merge.
