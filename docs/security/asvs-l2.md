# OWASP ASVS 4.0.3 Level 2 — BidRadar control checklist

SPEC 11 names "OWASP ASVS L2 checklist" as a launch requirement. This is that checklist,
one section per ASVS chapter, with a status per control group and a pointer to the code,
the test or the document that backs it.

**Status vocabulary**

| status | meaning |
| --- | --- |
| **implemented** | the control exists and something fails the build if it regresses |
| **partial** | the control exists but has a named gap, written down here |
| **planned** | not built; the task or open question that owns it is named |
| **n/a** | the control does not apply to this architecture, with the reason |

Nothing here is marked implemented on the strength of intent. Where the honest answer is
"the code does this but nothing checks it", the status is **partial**.

_Last reviewed: 2026-09-27 (M7-06). Review again before launch and at each quarterly
restore drill._

## V3 — Session management

| # | Control | Status | Evidence |
| --- | --- | --- | --- |
| 3.1 | No session tokens in URLs | implemented | Bearer header only (`app/core/auth.parse_bearer`) |
| 3.2 | Tokens generated by the framework, high entropy | implemented | Auth.js HS256 JWT over `AUTH_SECRET` (32 random bytes) |
| 3.3 | Session timeout | implemented | `exp` is required and verified with a 10-second leeway (`app/core/auth.decode_token`, `REQUIRED_CLAIMS`) |
| 3.5 | Stateless token verification is complete | implemented | Signature, algorithm, expiry and all required claims are checked; tenant and role come from the token and nowhere else |
| 3.7 | Session bound to identity, not guessable | implemented | `sub`, `tenant_id` and `role` are claims; a request cannot name its own tenant |
| 3.8 | Logout / revocation | **partial** | JWTs are stateless, so a token is valid until `exp`. Role changes take effect at the next refresh (OQ-18). A revocation list is needed before we ship SSO de-provisioning |

## Open gaps, in the order they should be closed

1. **V14.4 security headers / CSP** — nothing sets them today.
2. **V12.6 SSRF address filtering** — a tenant-supplied URL can currently name a private address.
3. **V1.14 written threat model** — the design is documented; the threat model is not.
4. **V3.8 token revocation** — needed before SSO de-provisioning means anything.
5. **V6.4.2 field-key rotation** — needs a re-encryption pass.
6. **V14.3 /docs exposure in production** — decide, then enforce.
7. **V5 prompt-injection golden set** — the eval suite is still a placeholder.

Each of these is a real gap, not a formality. None of them is a reason to delay the
restore drill, which is the one control on this page that cannot be verified by reading.
