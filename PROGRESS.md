## Open questions

- OQ-1 (§14) Product name/domain: keeping the placeholder "BidRadar" everywhere; rename is a find/replace later.
- OQ-2 (§14) Internal tenant profile seed: seeding a placeholder internal tenant with empty profile; the owner fills UEI/NAICS/past performance via the wizard.
- OQ-3 (§14) SAM.gov key type: code assumes a single non-federal personal key per environment (`SAM_API_KEY`), quota-aware limiter defaults to 10 req/day headroom; a system account is a config change only.
- OQ-4 (§14) Indian state portals: Telangana, Karnataka, Maharashtra as proposed; IREPS/defproc shipped as documented stubs.
- OQ-5 (§14) SLED: no HigherGov licence assumed; SLED ships as a documented adapter stub with the paid-feed adapter interface.
- OQ-6 (§14) Hosting: GCP Cloud Run as specified (Terraform); Railway not implemented.
- OQ-7 (§14) Embeddings: Voyage `voyage-3` (1024-dim) default behind `EmbeddingProvider`; no in-region LLM endpoint for India (config flag reserved).
- OQ-8 (§13.4) The spec says the first loop iteration should stop after writing tasks.json for human review. The operator asked for autonomous completion, so the loop continues into M0 without waiting; tasks.json remains open for review and edits at any time.
- OQ-9 (§6 stage 3) The spec does not name a model class for the match rationale. Using Sonnet-class (`LLM_MODEL_RATIONALE`) as the cost-safe default; changeable in config.
- OQ-10 Local dev machine has no ClamAV or Tesseract binaries; both are behind pluggable interfaces with a no-op/fake in tests and real implementations in the Docker image.

- OQ-11 (§10.1 auth) Auth.js needs a database adapter for email magic links even with JWT sessions. Frontend ships a process-local in-memory adapter attached only when EMAIL_SERVER is set (marked TODO(M1)); the backend must expose users/accounts/verification_tokens so a real adapter replaces it. Also `resolveMembership(email)` in the frontend is an env-fallback stub until the backend membership lookup exists.
- OQ-12 (§10.1 files) MinIO no longer publishes public Docker images (docker.io and quay.io both deny anonymous pulls as of 2026-09-27). Local compose uses RustFS (S3/MinIO API-compatible, same ports and credential envs). Production stays GCS.
- OQ-13 (local dev) Docker Desktop's `credsStore: desktop` credential helper hangs on this machine (no interactive keychain), blocking every image pull. Workaround: run compose with `DOCKER_CONFIG` pointing at a copy of ~/.docker that omits `credsStore` (see docs/runbooks/local-docker.md once written). Images are now cached locally so plain `make up` works.
- OQ-14 (§2 rows 7-9, §14) Indian portal pre-flight: mahatenders.gov.in robots.txt is `Disallow: /` so Maharashtra must NOT be crawled (ship as link-only, health robots_disallowed). tender.telangana.gov.in and eproc.karnataka.gov.in are not GePNIC (custom platforms; Karnataka unreachable). Confirmed GePNIC portals with permissive robots: tntenders.gov.in (Tamil Nadu), etender.up.nic.in (Uttar Pradesh), etenders.gov.in (central). Proposed v1 GePNIC set: TN, UP, central GePNIC; Telangana via its own portal in phase 2. bidplus.gem.gov.in refused connections from this host; GeM adapter is fixture-driven until smoke-tested from a cloud region.

- OQ-15 (CLAUDE.md core purity vs M0 design) The tenant session factory lives at app/core/db.py as decided for M0, although CLAUDE.md says core/ is I/O-free. It is exercised by integration tests against the compose Postgres, so the core coverage gate still measures it honestly. If a later milestone prefers purity, move it to app/db.py and keep `get_session(tenant_id)` re-exported.

- OQ-16 (§3/§11 users table) Postgres applies the SELECT policy to INSERT ... RETURNING, so the app role (which only sees users through a membership in the current tenant) can never insert a brand-new user. Decision: users and their first membership are provisioned by the owner role inside app/services/users.py (JIT on first authenticated request, and by the seed); every other users read/write goes through the app role under RLS.

- OQ-17 (§11 auth rate limit) The per-IP failed-auth limiter is in-process (app/core/ratelimit.FixedWindowLimiter) for M0; with several Cloud Run instances the effective limit is N x 20/min. A Redis-backed limiter with the same hit/is_limited interface is a follow-up in the hardening milestone.
- OQ-18 (§3 roles) RBAC uses the role claim in the Auth.js token; the memberships row is created JIT and never re-roled by the API. Role changes therefore take effect at the next token refresh. If the DB must be authoritative per request, add a membership lookup in get_current_user (one indexed query).
